安全

AI 应用的安全面比传统 Web 应用更广——除了常规的鉴权与数据隔离，还要面对 Prompt 注入、模型输出不可控、工具调用越权等 LLM 特有的风险。本章从成本防护、输入安全、输出安全、鉴权与数据隔离、工具执行安全五个维度展开。

Token 成本防护

LLM 调用按 Token 计费，失控调用会直接导致成本爆炸。语图在三个层级做防护：

用户级：每用户每日 Token 配额上限，超阈值触发降级（切换到更小模型）或直接中断。配额按"生成"与"修改"分别计量——生成场景 Token 消耗远大于修改，分开统计才能精准管控。

会话级：单次会话设置 Token 软上限。当累计消耗超过阈值时，系统主动提示用户"当前会话已消耗较多资源"，避免长对话无限制累积。

调用级：单次 LLM 调用设置 max_tokens 硬上限，防止模型输出失控膨胀。配合 Zod Schema 校验，输出超长时直接截断并触发反思重试，而不是让超长内容流入下游。

为什么不用简单的"请求次数"限流

Token 消耗与请求次数不成正比——一次 generate 可能消耗 3000 Token，一次 consult 只消耗 200。按 Token 计量才能真实反映成本，按请求次数限流会导致"一次重请求"和"十次轻请求"占用相同配额。

输入安全：Prompt 注入防御

Prompt 注入是指用户通过精心构造的输入，试图覆盖 System Prompt 的指令，让模型执行非预期行为（如泄露系统提示词、绕过安全限制）。

防御策略

语图采用分层防御，不依赖单一手段：

层级手段说明
输入预处理关键词/模式过滤检测"忽略以上指令""你现在是"等典型注入模式，命中时直接拒绝或改写
System Prompt 加固角色锚定 + 边界声明在 System Prompt 开头和结尾重复强调角色边界，如"你是流程图生成助手，不会执行与流程图无关的任务"
输出校验Zod Schema + 图结构验证即使注入成功影响了模型输出，确定性校验层仍会拦截不合规的结构
工具调用隔离白名单机制模型只能调用预注册的工具，无法通过注入让模型"发明"新工具或调用敏感 API

为什么分层而不是单点

单靠 Prompt 加固不够——模型是概率性的，无法 100% 拒绝注入。但即使注入绕过了 Prompt 防线，后续的结构化校验（Zod Schema）和工具白名单仍会兜底。这就是"确定性优先"原则在安全领域的体现：不信任任何单一层的判断，用确定性程序做最终兜底。

输出安全：结构化错误与降级不泄密

模型和工具产出的错误信息中可能包含数据库连接串、内部 IP、文件路径、API Key 等敏感信息。如果直接把这些错误丢给模型做上下文，模型可能在回复中"不经意"泄露给前端用户。

错误信息脱敏

所有工具执行结果经过结构化转换层，原始错误被替换为对模型安全的摘要（完整的失败分类、重试与降级策略见工具调用）：

// 原始错误（不暴露给模型）
{ error: "ECONNREFUSED 10.0.1.5:5432", detail: "pg_connect: password auth failed for user 'admin'" }

// 结构化后（模型看到的）
{ status: "fail", message_for_llm: "数据服务暂时不可用，请稍后重试" }

降级提示受控

工具失败时的降级提示由 System Prompt 引导，措辞受控。模型不会自由发挥解释失败原因，而是使用预设的话术模板，避免在降级场景中暴露底层实现细节。

鉴权与传输安全

  • Redis + JWT 登录鉴权：用户登录后发放 JWT，同时存储在 Redis 中用于服务端校验（支持主动失效、单点登录等场景）。每次请求由 JwtAuthGuard 拦截验证。
  • Token 过期与刷新：JWT 设置合理过期时间（如 2h），过期后通过 refresh token 机制无感续期。
  • HTTPS 强制：生产环境所有请求走 HTTPS，防止中间人攻击和 Token 嗅探。
  • CORS 白名单：后端只允许已知前端域名跨域访问，拒绝通配符 *。

数据隔离

多租户/多用户场景下，数据隔离是安全底线。语图在三个维度做隔离：

跨项目记忆隔离：每个项目的记忆数据（短期 Checkpointer + 长期 Store）按 project_id 命名空间隔离。Agent 在处理项目 A 的对话时，不会召回项目 B 的记忆。

用户画像独立命名空间：用户画像按 user_id 隔离存储，不同用户的数据互不可见。画像的读写都通过命名空间路由，不存在跨用户泄露的可能。

编辑器数据隔离：PostgreSQL 中的流程图文档（JSONB）通过 projectId 关联，查询接口强制校验当前用户对该项目的访问权限，防止越权访问他人文档。

工具执行安全

Agent 能调用的工具（Function Call / Skill / MCP）是攻击面最大的环节——如果模型被注入诱导，可能尝试调用敏感工具或传入恶意参数。

防护手段说明
工具白名单只有预注册的工具可被调用，模型无法"发明"新工具
参数校验每个工具入口用 Zod Schema 校验参数类型与范围，非法参数直接拒绝
最小权限工具只暴露必要能力，不暴露数据库直连、文件系统访问等高危操作
调用审计每次工具调用记录到 Langfuse trace，事后可追溯完整调用链
