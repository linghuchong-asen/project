# 质量属性

语图作为 LLM 驱动的 Agent 应用，质量属性不同于传统 CRUD 系统——核心挑战在于模型输出的不确定性、长链路状态管理的复杂性、以及 Token 成本的可控性。本章从可靠性、可用性、可观测、可扩展、安全性五个维度，梳理各章节中散落的质量保障设计，形成全局视图。

## 可靠性

模型是概率性的，可靠性设计的本质是"用确定性代码兜住模型的不确定性"。

| 机制 | 实现方式 | 相关章节 |
|------|---------|---------|
| 模型输出可控 | 模型只输出 FlowDraft 语义结构（无坐标/样式/ports），出错搜索空间从 X6 完整 JSON 收窄到 4 字段 | [介绍](./index.md) · [前端](./frontend/index.md) |
| 两层反思校验 | Zod Schema 格式校验 + 图遍历结构校验，命中断头/缺分支/未闭环等确定性规则即阻断重生成 | [反思反馈](./reflection.md) |
| 分层 diff 防误删 | L1 ID 精确匹配 → L2 语义匹配 → L3 拓扑匹配 → L4 边校验，模型漏写 ID 时不误删节点 | [介绍](./index.md) |
| 工具失败分级处理 | 网络错误代码重试、参数错误让模型自修正、重试耗尽走降级，结构化错误不丢原始堆栈给模型 | [工具调用](./tool-calling.md) |
| 模糊语义不盲改 | 反思层遇模糊语义（如分支标签歧义）不自行猜测，交用户确认后再回生成节点 | [反思反馈](./reflection.md) |

## 可用性

可用性关注用户在对话和画布交互中的体验流畅度，以及资源不被浪费。

| 机制 | 实现方式 | 相关章节 |
|------|---------|---------|
| 思考流式 + 数据一次性 | CoT 思考过程走 SSE 逐 token 推送，FlowDraft JSON 走 fetch 一次性拉取，数据源分离 | [流式输出](./streaming.md) |
| SSE 连接生命周期 | AbortController 显式管理连接，前端断开时 abort 后端 Observable，LangGraph 节点执行前检查 abort signal | [流式输出](./streaming.md) |
| 意图识别零延迟路由 | 规则命中（动词特征 + 上下文状态）直接路由，零模型调用成本，仅边界情况交模型兜底 | [意图识别](./intent.md) |
| 增量修改保留用户布局 | modify 时未变化节点保持原样（含手动坐标），修改节点只更新内容字段，新增节点才重算位置 | [介绍](./index.md) |
| Token 预算管控 | 输入卡模型上下文上限 80%，上下文组装环节按占比截断畸高部分，控总量为主、控条数兜底 | [上下文管理](./context.md) |

## 可观测

LLM 应用是黑盒，可观测性是持续迭代的前提——trace 定位问题，评估量化质量，两者共同支撑发版决策。

| 机制 | 实现方式 | 相关章节 |
|------|---------|---------|
| Langfuse 全链路 trace | 追踪意图识别→上下文组装→工具调用→生成→反思完整轨迹，记录每节点输入/输出、Token 消耗、模型延迟 | [评估与可观测性](./evaluation.md) |
| HTTP 请求日志 | 请求日志中间件记录 method/url/body/query/ip，TransformInterceptor 记录响应，HttpExceptionFilter 记录异常堆栈 | [后端](./backend/index.md) |
| 轨迹评估 | 不只看最终输出，评估 Agent 完整执行轨迹：工具调用次数、反思回路次数、错误恢复步数 | [评估与可观测性](./evaluation.md) |
| 发版回归闸门 | 固定用例集全量回归，格式合规率 100%、意图识别准确率 ≥95%、工具调用成功率 ≥98%，任一跌破不发布 | [评估与可观测性](./evaluation.md) |
| 生产监控告警 | Langfuse API 拉取错误率/延迟/Token 消耗接入告警，异常时直接查 trace 链路定位根因 | [部署](./backend/deploy.md) |

## 可扩展

可扩展性关注系统在不改架构的前提下适配新能力的能力。

| 机制 | 实现方式 | 相关章节 |
|------|---------|---------|
| 中间层解耦渲染引擎 | FlowDraft 是纯语义结构，前端转换层负责映射到 X6；切换渲染引擎（如思维导图）只需改转换层和映射表 | [前端](./frontend/index.md) |
| Skill 配置化动态注册 | 工具定义（名称/描述/参数 Schema/执行器）配置化，用户前端表单配置，后端动态注册到 ToolNode | [工具调用](./tool-calling.md) |
| 模型分层策略 | 高级模型管生成、中参数模型管反思、规则管意图，按任务复杂度分配算力，模型切换改配置不改编排 | [介绍](./index.md) |
| 记忆分层独立演进 | 短期（Checkpointer）/长期（Store）/画像（独立命名空间）三层分离，各层策略可独立调整 | [记忆管理](./memory.md) · [AI 编排运行时](./ai-runtime.md) |
| 统一存储扩展 | PG 一身多职（关系+JSONB+向量+全文检索），新增数据形态不引入新组件 | [存储层设计](./backend/storage.md) |

## 安全性

AI 应用的安全面比传统 Web 应用更广，除常规鉴权外还要面对 Prompt 注入、工具越权、Token 滥用等 LLM 特有风险。

| 机制 | 实现方式 | 相关章节 |
|------|---------|---------|
| Token 配额管控 | 用户级每日 Token 配额，按 generate/modify 分开计量，超阈值降级或中断 | [安全](./security.md) |
| Prompt 注入防御 | 输入消毒、System Prompt 边界约束、工具调用白名单，模型无法"发明"新工具或调敏感 API | [安全](./security.md) |
| 结构化错误不泄密 | 工具失败转结构化错误返回模型，原始堆栈不进 context，降级提示用预设话术模板 | [工具调用](./tool-calling.md) · [安全](./security.md) |
| 多维度数据隔离 | 跨项目记忆按 project_id 命名空间隔离，用户画像按 user_id 隔离，编辑器文档查询校验访问权限 | [安全](./security.md) · [存储层设计](./backend/storage.md) |
| 回滚保障 | 代码（Docker tag）、Prompt（版本控制）、模型（环境变量配置）、数据（Checkpointer 检查点）四层独立回滚 | [部署](./backend/deploy.md) |
